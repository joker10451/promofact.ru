# CATALOG-1 — безопасное обновление Admitad

## Фактическое состояние (16.10.2026)
- В таблице admitad_coupons: 437 активных записей из 74 кампаний.
- 22 строки имеют дату expires ранее 16 октября; публичный сайт скрывает просроченные акции при отображении.
- Последний успешный authoritative snapshot: 13 октября 2026 в 23:44 UTC.
- URL и ERID совпадают по агрегированной проверке. Это не подтверждение реальных кликов или заказов.
- Старый восьмипрограммный batch не должен перезаписывать широкий publisher-scoped каталог.

## Процесс
- Workflow: Admitad Publisher Website Coupon Catalog.
- Расписание: каждые 6 часов, только preview, без записи в Supabase.
- Pull request из того же репозитория: preview без записи.
- Ручной запуск: preview или publish с явным подтверждением.
- Одна группа concurrency admitad-publisher для сериализации синхронизаций.
- В логах только агрегаты; коды, персональные данные, ссылки, ERID и OAuth-секреты не выводить.

## Гейты
1. Сверяем метаданные последнего успешного снимка с активными ID; пустая, обрезанная, неуспешная или слишком старая база блокирует обновление.
2. Проверяем ID, даты, HTTPS-ссылки, erid-параметр, ОРД-текст и юридические статусы.
3. Новые кампании запрещены: допускаются новые coupon IDs только от программ уже существующего снимка, максимум 25 за один проход.
4. Сначала запускаем worker в skipDbWrite режиме с retention-check, порогом роста и контролем каталога.
5. Перед ручной записью повторно проверяем поколение, ID, кампании, срок, ссылку и ERID. Если изменилось — отказ.
6. При явно одобренном запуске worker публикует новый снимок через атомарную PostgreSQL RPC. После неё проверяем count и отсутствие новых кампаний.
7. Истёкшие предложения могут быть деактивированы, но действующие предложения нельзя тихо удалять.

## Безопасная ручная публикация
1. В GitHub Actions выберите Admitad Publisher Website Coupon Catalog, затем Run workflow и mode=preview.
2. Дождитесь PREVIEW_PASS; проверьте количество будущих активных предложений и изменения сроков.
3. Сверьте разрешения и актуальные условия в Admitad. Только затем выберите mode=publish и confirm.
4. После записи проверьте PUBLISHED, число предложений, отображение на сайте и корректность ERID, не совершая фиктивных покупок.

## Ошибки и восстановление
- Preview и заблокированная до RPC публикация не меняют Supabase.
- RPC атомарна, но автоматического отката уже успешно опубликованного поколения нет. При ошибке после публикации нельзя слепо запускать workflow повторно. Остановите повторные операции, сохраните run ID, используйте проверенный backup или PITR только после отдельного анализа и согласования.
- Старый admitad-batch.yml не является способом обновления полного каталога.

## Отчётность и доход
- На сайте уже вызываются цели Яндекс.Метрики copy_code, copy_and_open и affiliate_click; они измеряют взаимодействия, а не совершённые покупки.
- Подтверждённые комиссии Admitad и Perfluence потребуют отдельной интеграции с transaction reports и статусами pending/approved/rejected. Не показывать доход и конверсии как подтверждённые без транзакционных данных. Не передавать сами промокоды и личные данные в Метрику.
