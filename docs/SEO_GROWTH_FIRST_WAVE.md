# ПромоФакт — первый SEO-этап, 20 магазинов + 5 тематических подборок

Дата первичного среза: **20.10.2026**. Источник приоритизации магазинов:
read-only SQL по `public.admitad_coupons`, активные записи с неистёкшей датой.
Это **число предложений в одном источнике**, не трафик, не выручка,
не подтверждение работоспособности кода в корзине и не итоговая выдача
после объединения с Perfluence, ручными офферами и дедупликацией.

## Первая фактическая реализация

- Уже существующие тематические подборки не создаются повторно:
  `first-order`, `food-delivery`, `vecher-kino`, `krasota-i-parfyum`,
  `vygodnye-oteli`.
- Для каждой добавлены **3 уникальные практические проверки для покупателя**.
  Текст не обещает применение конкретного кода, размер скидки или наличие товара.
- Все страницы `/collections/[slug]` и `sitemap.xml` переведены на ISR **900 с**,
  чтобы обновления каталога были видны без нового Vercel-деплоя.
- `robots: noindex, follow` для подборок, у которых менее 3 доступных
  предложений после тех же ограничений на сочетания рекламодателей, которые
  используются при показе. Эти страницы исключаются из sitemap; при появлении
  предложений могут снова индексироваться. Пустым разделам оставлена
  навигация в каталог.
- Не утверждать «проверено сегодня», «точно работает», «скидка применится
  сразу», не создавать шаблонные почти одинаковые SEO-страницы массово.

## Измерение результатов и критерии успеха

Начальные показатели Google Search Console и Яндекс Вебмастера не получены
из подключённых источников, поэтому **не подставлять нулевые значения**.
Нужен бесплатный доступ к первичным отчётам: поисковые запросы, показы,
клики, CTR, средняя позиция, индексирование этих 25 URL. Проверять
каждые 7 дней и через 28 дней сравнить динамику.

Сайт: события `copy_code`, `affiliate_click`, `home_offer_open` в
Яндекс.Метрике; проверять поступление настоящих событий (не тестировать
кликами по рекламным ссылкам) и отдельно согласованные заказы в партнёрских
системах. Разница между поисковыми кликами, кликами по купонам и оплатами
не должна смешиваться в одном показателе.

**Запрет на пустое SEO:** URL с недостаточным каталогом исключаем из sitemap,
а не заменяем выдуманными скидками. Не менять ERID, не обещать проверку
промокода без покупки, не убирать действующие промокоды с главной.

Методика:
- Google Search Central: https://developers.google.com/search/docs/essentials/spam-policies
- Яндекс Вебмастер: https://yandex.ru/support/webmaster/ru/site-quality-index


## Продолжение: редакционные памятки в карточках магазинов (20.10.2026)

Первый пакет проработки страниц магазинов — восемь существующих канонических URL:
`hollyshop` (`admitad-29791-hollyshop`), `Яндекс Практикум`
(`admitad-25914-yandex`), `МегаФон`, `Korston`, `SUNLIGHT`,
`Фоксфорд`, `Aravia` и `Яндекс Путешествия`.

У каждого — три тематические проверки перед заказом и отдельный вводный
абзац на основании известного типа магазина. Редакционная памятка видна
после предложений и таблицы сравнения. **Не** заявляем, что купон прошёл
проверку в корзине; текст появится только при наличии текущих предложений.
Партнёрские ссылки, правила co-promotion и ERID не менялись.

Главная проверяемая проблема: до исправления Яндекс Практикум мог получать
универсальный SEO-абзац о маркетплейсах при некорректной категоризации
старого снимка. Теперь абзац для образовательной программы зависит от
**канонического slug**, а не случайной/устаревшей категории.

Это **не гарантирует новые показы или заказы**. Следующий этап — 12
остальных страниц из списка и анализ реальных запросов. Базовые показатели
Google Search Console / Яндекс Вебмастера пока не получены; не
подставлять фиктивные CTR и конверсию. Для проверки контента предусмотрен
`npm run test:seo-store-guides`.

### Обнаружено в данных источника — не исправлялось автоматически

- У Globus категория в снимке источника «Сервисы и подписки», но
  текущие офферы относятся к заказам товаров. Для текста теперь
  используется канонический slug и реальные условия, а не ошибочная
  категорийная заготовка.
- В отдельных записях POLZAru процентная скидка из поля `discount`
  противоречит денежной величине из `terms`. Не транслировать такое
  предложение как доказанную скидку без проверки. Любое исправление
  отображаемого размера выгоды должно быть отдельной диагностикой
  и не должно изменять оригинальные данные партнёра.

Режим работ: только один PR с тестами и одним контролируемым выпуском;
никаких изменений партнёрских ссылок, фальшивых покупок, автогенерации
кодов или новых тонких URL.
