# Admitad — ежедневное безопасное обновление каталога

После восстановления каталога 20.10.2026 основной источник — 449 активных
предложений из уже разрешённых программ площадки «ПромоФакт». В задаче #124
зафиксированы исходные данные и однократная процедура восстановления.

## Что запускается автоматически

`.github/workflows/admitad-publisher-catalog.yml`: ежедневно в **04:27 UTC**
(07:27 по Москве), только в основной ветке GitHub. Запуск не изменяет код, не
создаёт Git-коммиты и **не вызывает Vercel-деплой**.

1. Проверка прав доступа к площадке Admitad и пригодности текущей базы.
2. Полный read-only preview с `skipDbWrite: true`, проверкой действующих
   кампаний, ERID, юридической маркировки, идентичности и сроков.
3. Сверка базы непосредственно перед публикацией (включая поколение, ERID,
   ссылки и сроки). Если она изменилась — остановка.
4. Только после успешного preview — атомарная публикация **существующих**
   одобренных кампаний в Supabase.
5. Контроль нового количества и отсутствия новых неразрешённых кампаний.

Ограничения: не более **25 новых купонов за запуск**, без добавления
новых рекламодателей, не удалять неистёкшие офферы без заранее проверенного
точечного исключения и нового подтверждения отзыва в Admitad, отказ при
расхождении ERID, неправильных ссылках, устаревшей базе (старше 7 дней)
или превышении лимита. Предупреждение: прохождение автоматических проверок
не подтверждает, что промокод примут в корзине магазина.

## Аварийная остановка

GitHub репозиторий → **Settings → Secrets and variables → Actions → Variables**:
установить `ADMITAD_PUBLISHER_AUTO_SYNC_ENABLED` равным `false`.
Следующие плановые запуски не начнут работу. Удаление переменной или значение,
отличное от `false`, вновь разрешает автоматизацию. Уже выполняющийся запуск
отменяется через GitHub Actions вручную.

Бывший `admitad-batch.yml` больше **не имеет cron**; его ручной запуск
остаётся с подтверждением и собственными защитами. Оба сценария используют
группу `admitad-publisher`, не выполняются одновременно.

## Проверка работоспособности

- Actions → `Admitad Publisher Website Coupon Catalog`: искать
  `CATALOG_1_PREVIEW_PASS` и `CATALOG_1_PUBLISHED`, оба с ожидаемыми
  агрегатами и `databaseWrites` 0/1.
- Supabase → `admitad_sync_meta`: статус `SUCCESS`, свежие
  `last_success_at` и `last_success_count`; число активных
  `admitad_coupons` должно совпадать.
- Если workflow завершился ошибкой, **не отключать retention** и не
  исправлять офферы вручную в SQL. Проверить причину, заново выполнить
  только `preview`, согласовать безопасное устранение.

Ручной режим `workflow_dispatch mode=preview` остаётся read-only.
`mode=publish` требует отдельного `confirm=true`.
