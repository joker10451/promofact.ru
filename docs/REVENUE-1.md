# REVENUE-1: подтверждённые комиссии vs клики PromoFact

## Уже есть
- ПромоФакт: Яндекс.Метрика отслеживает promo_show, copy_code, copy_and_open, affiliate_click.
- Для ссылок Admitad передаются subid=placement, subid1=pageType, subid2=couponID, subid3=promofact, subid4=случайный clickID.
- Сам по себе переход, копирование кода, показ карточки и даже зафиксированное действие не означают подтверждённый доход.

## Новый источник: Admitad Statistics API
- Официальный GET https://api.admitad.com/statistics/actions/, scope=statistics. Отдельный OAuth client_credentials запрос, не используем токен доступа к каталогам с другим scope.
- Только ADMITAD_WEBSITE_ID площадки ПромоФакт; date_start и date_end в формате ДД.ММ.ГГГГ.
- Режим только чтение. Нет записи в Supabase, IndexNow, GitHub репозиторий, сайт или Perfluence.
- Собираем по action_id с дедупликацией, но никогда не печатаем ID действий, номер заказа, промокод, субид4, IP или персональные сведения.
- Статусы: pending — в обработке, approved — подтверждённая комиссия, approved_but_stalled — подтверждена, но задержана к оплате, declined — отклонена, unknown — неизвестный статус. Их суммы нельзя смешивать.
- paid=1 показывает выплату по отдельным действиям, но approved не гарантирует вывод денег.
- sale и lead — различные виды действий; совокупный sales_sum без статусов не является количеством подтверждённых продаж.
- Данные рублёвые, долларовые и в евро никогда не складываются без курса и отдельного соглашения.
- Атрибуция к конкретным ссылкам возможна только при subid3=promofact; действия без маркера считаются неатрибутированными. Нельзя из статистики Метрики напрямую выводить заказ или прибыль.

## Безопасное подключение
1. Убедитесь, что Admitad OAuth-приложению разрешён scope statistics. Его наличие у обычного купонного токена не следует предполагать.
2. После слияния PR вручную запустите GitHub Actions → REVENUE-1 Admitad Read-Only Connectivity → Run workflow.
3. Workflow выведет только статус подключения, дату периода и перечень валют. Суммы скрыты, поскольку логи GitHub могут быть публичными.
4. Для просмотра реальных подтверждённых сумм запускайте скрипт в приватном окружении с настроенными ADMITAD_CLIENT_ID, ADMITAD_CLIENT_SECRET, ADMITAD_WEBSITE_ID и REVENUE_1_PRIVATE_REPORT=true:
   node --loader ./scripts/ts-loader.mjs scripts/revenue-1-preview.mjs
5. Период по умолчанию: последние 28 календарных дней по UTC; при необходимости укажите REVENUE_1_DATE_START / REVENUE_1_DATE_END в формате ГГГГ-ММ-ДД (не более 90 суток). Статусы прошлых заказов могут меняться; это текущий снимок, не история выплат.
6. Отчёт выводится только в stdout приватного терминала; API-ответ и идентификаторы покупателей на диск не сохраняются.

## Perfluence: источник ещё не аттестован
Старый scripts/perfluence-earnings-monitor.mjs читает json.data[].fee по PERFLUENCE_RESULTS_URL, но в нём нет подтверждённой схемы статусов заказов или выплат. Поэтому fee нельзя объявлять одобренным, заработанным или выплаченным доходом. Новый инструмент проверяет наличие фида Perfluence только как UNVERIFIED (без сумм). Подключение подтверждённых доходов возможно после получения документированного отчёта о статусах, срезе по площадке promofact.ru и правилах дедупликации.

- После проверки реального API и схемы Perfluence реализовать сверку изменяющихся статусов и защищённую историю финансовых операций без PII.
