# Ежедневный контроль купонов ПромоФакта

Workflow: `.github/workflows/daily-coupon-watch.yml`. Первый запуск — вручную через **GitHub → Actions → Daily Coupon Health Watch → Run workflow**. Далее GitHub пытается запускать его ежедневно **в 08:10 по Москве (05:10 UTC)**. Очереди GitHub Actions могут задерживать запуск.

**Важное:** этот процесс не синхронизирует и не публикует купоны, не делает `git push`, не создаёт production-сборки Vercel, не посещает рекламные URL (чтобы не накручивать переходы) и не изменяет Supabase. Это исключительно **контроль и оповещение**.

## Источники

1. **Ручные размещения:** `src/lib/customCoupons.ts`, включая Магнит, М.Косметик, Ситидрайв и Подружку. Проверка включает отдельный тип EAN-13 / кассового штрихкода.
2. **Диагностический снимок Perfluence:** GET `https://promofact.ru/api/perfluence-audit`. Он содержит и неподтверждённые предложения, включая оригинальную ссылку `affiliate.sourceLink`, сохранённую до нормализации, чтобы мониторинг не скрывал ошибки ERID. Эти данные **нельзя использовать для публикации**. Отдельный GET `/api/perfluence-snapshot` отдаёт только активные, прошедшие фильтр безопасности предложения для резервного источника сайта. Ни один снимок не показывает все внутренние акции личного кабинета Perfluence.
3. **Опубликованные предложения Admitad:** read-only SELECT таблицы `admitad_coupons` с фильтром `is_active=true`; staging-таблица никогда не используется как живой каталог. Для GitHub Actions нужны уже существующие секреты `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. При отсутствии обоих скрипт явно сообщает **skipped**, а не «0 купонов».

Проверяются: сроки с точным московским временем, реальные коды и акции по ссылке, HTTP(S)-ссылки, несовпадение `ordMarker` / `ordText` / параметра `erid` в партнёрском URL; новые/пропавшие коды и изменения условий/ссылок по сравнению с предыдущим успешным запуском.

**Исходный ERID Perfluence:** если оригинальная `sourceLink` не содержит `erid`, но фид предоставил непротиворечивый `ordMarker` и итоговый URL содержит этот токен, это предупреждение, а не доказательство незаконной рекламы. Отсутствие токена и в исходных данных, несоответствие меток или подмена исходного домена/ERID — критическая ошибка. Если история исходного URL недоступна (например, из старого резервного снимка), система явно пишет, что исходный URL проверить нельзя. Если исходные ссылки отсутствуют у 50% или более активных Perfluence-предложений, снимок помечается аномалией и **не заменяет последний успешный baseline**. На публичных страницах исходные ссылки не показываются. Лимит строк отчёта не влияет на счётчики ошибок, критические записи идут первыми.

При временном сбое источника старое состояние **не стирается**: первая неудача — предупреждение, после второй подряд — тревога. Пустой каталог или резкое сокращение (50% или больше ещё действовавших записей) Perfluence/Admitad считается **аномалией источника**, а не подтверждённым исчезновением всех кодов: сохраняется последний успешный снимок, мониторинг сразу поднимает тревогу. Запланированное окончание срока действия не учитывается как потеря источника. История сохраняется в GitHub Actions cache даже при красном результате проверки.

## Где результаты и уведомления

- Каждый запуск: **Actions → Daily Coupon Health Watch → Summary** (короткий Markdown).
- На 30 дней: артефакт `coupon-watch-N` с Markdown и JSON.
- Изменения и значимые проблемы: один открываемый/обновляемый GitHub Issue **«[Каталог] Требуется проверка промокодов»**. После исчезновения новых проблем он закрывается автоматически.
- Для получения оповещений GitHub на почту включите **Watch → Custom → Issues** (или подпишитесь на конкретный Issue).
- Критическое несоответствие ссылки и маркировки, пустая партнёрская ссылка или 2 подряд недоступных запуска делают Action красным. Остальные изменения отображаются в отчёте/Issue.
- Состояние предыдущего запуска хранится только в **GitHub Actions cache**, без коммитов в `main`; когда cache удалится, первый запуск будет новой исходной точкой.

## Что мониторинг НЕ умеет

- Подтвердить применение купона в корзине, реальные ограничения, выдачу подарка или сканирование кассового штрихкода.
- Увидеть внутренние промокоды Perfluence, не попавшие в публичный фид или ручные размещения.
- Автоматически исправить истёкшие акции или выдумать новый `erid`.
- Уведомить лично в мессенджер без отдельной настройки уведомлений или подписки на GitHub Issues.

## Запуск и тесты

```bash
npm ci
npm run test:coupon-watch
npm run audit:coupons:daily
```

Отчёт и baseline: `audit-results/coupon-watch-report.md`, `audit-results/coupon-watch-report.json`, `audit-results/coupon-watch-state.json`. Не включать эти runtime-файлы в коммит.

Ежедневный контроль дополняет **еженедельную** безопасную синхронизацию `sync-catalog.yml` и не заменяет согласование рекламы в Perfluence/Admitad.
